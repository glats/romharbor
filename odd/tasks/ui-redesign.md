# ui-redesign
Objective: redesign the ROMHarbor web interface on the same base (Go templates, htmx, no SPA) so it is usable now, shows downloads, filters, and makes Knulli compatibility visible and enforced.
Branch: feat/ui-redesign (from main at the K4 close). Delivery: ask-on-risk. Runner: `TMPDIR=/tmp/opencode GOTOOLCHAIN=local nix shell nixpkgs#go_1_25 -c sh -c '...'`.

## Specs
S1. Same base. User answer, verbatim label: "Rediseño visual, misma base" — server-rendered Go templates and htmx; no SPA, no new frontend build.
S2. Scope, user answer verbatim: "Estilo general, Ver descargas, Buscar y filtrar, Compatibilidad a la vista, siempre se tiene que forzar a la compatibilidad con canoris pero si no bueno le ponemos la etiqueta" (assumption: "canoris" is Knulli). Four areas: general style (colors, typography, cards, light and dark theme: assumption from the offered option), visible downloads panel (in progress, done, failed, with progress), search and filter (global search across platforms, filters, order), compatibility shown on each game.
S3. Knulli compatibility rule (assumption from S2, to be confirmed by the user): the catalog prefers and forces the Knulli-compatible variant by default; when a game has no compatible variant it is still listed with a label that says why (translation, beta, PAL, prototype, heavy title). The rules come from the compatibility research in `odd/roadmap.md` (clean No-Intro/Redump over translations, hacks and betas; `.z64` for N64; NTSC/US over PAL; CHD over cue/bin).
S4. Out of scope until the user asks: new cores in the NixOS repository, `.m3u` handling (K6/N-03), publishing, tag, pin.

S5. Decisions taken by the parent without a question, from the explorer recommendations (reversible, user may overrule): "canoris" is Knulli; global search box on `/` grouped by platform; light and dark theme with automatic default and a manual toggle; the downloads panel lists all jobs newest first (K4 cap 500); the compatible variant is preferred at listing time and incompatible ones stay listed with labels only when no compatible variant of that title exists.

## Tasks
- T1 [S3,S5] delegated writer A, worktree `ui-a` — domain: Knulli compatibility classifier and variant preference. Surface: `internal/domain/rom/**` (new files and tests), `internal/app/query/**` (new file and tests only). (a) `rom.Compatibility{Compatible bool, Labels []string}` and `func KnulliCompatibility(g Game, p Platform) Compatibility`, pure, derived from No-Intro and Redump tags in the title and file names: `[!]` good, `[b]` bad dump, `[h...]` hack, `[T+...]` or `[T-...]` translation, `(Beta)`, `(Proto)`, `(Prototype)`, `(Demo)`, `(Sample)`, `(Unl)`, region `(USA)`, `(U)`, `(World)`, `(Europe)`, `(E)`, `(Japan)`, `(J)` (PAL = Europe, E, Australia, A), `(Disc N)`, plus platform rules (N64 heavy titles Banjo-Kazooie, Banjo-Tooie, GoldenEye 007, Donkey Kong 64, Majora's Mask labeled `heavy`, still compatible=true; formats not accepted by the platform extensions; `.z64` preferred label for n64 `.n64`/`.v64`). Compatible=false for translation, hack, bad dump, beta, prototype, demo, sample, unlicensed; PAL is compatible=true with label `pal`. Labels are short lowercase English tokens. (b) `func PreferCompatible(games []Game, p Platform) []Game`: group by the base title (title without any parenthesis or bracket tags); within a group keep the best variant (compatible first, then verified `[!]`, region order us, world, europe, japan, others, then larger-disc stability) and drop the others when at least one compatible variant exists; when none is compatible keep all, so the UI labels them; stable output order; multi-disc titles (`(Disc N)`) stay as separate entries. (c) global search in `internal/app/query`: a query handler that searches every platform for a text and returns games grouped by platform, reusing the existing listing query and the existing decorators (logging, metrics); partial failures reported the way `SearchGames` does; do not touch `internal/port/web` or `internal/app/app.go` (report the wiring needed). Tests: table tests with the real tag shapes (the explorer found no fixtures with `[T+]`, `(Beta)`, `[h]`, `[b]`, `(Disc N)`: add them), observed RED first. ~450 lines.

Observed: covers are libretro thumbnails (`https://thumbnails.libretro.com/<set>/Named_Boxarts/<title>.png`) requested straight from the browser with `loading="lazy"` already set; many titles return 404 (e.g. 007 - The World Is Not Enough (USA)) and the image is hidden on error, leaving an empty card. Decision (parent, reversible): a same-origin cover proxy with an on-disk cache, a bounded upstream pool, negative caching and a skeleton/placeholder in the card. Spec S6 below.
- S6: Cover images are served by `GET /cover?platform=<slug>&title=<title>`: the host is always the platform's libretro set (no arbitrary URL), the first request fetches and stores the image on disk under `<ROM_CACHE>/covers`, later requests are served from disk with `Cache-Control: public, max-age=604800, immutable`; a missing cover (404 upstream) is remembered for 24 hours and answers 404; an upstream failure is remembered for 2 minutes; at most 4 upstream fetches run at once, concurrent requests for one cover share one fetch; each fetch has a 15 second timeout and a 2 MiB cap. The card shows a title placeholder with a skeleton shimmer while the image loads, fades the image in, and keeps the placeholder when it fails. `/api/*` JSON stays byte-identical (`Cover` keeps the upstream URL).
- L9: Root cause of the covers that never load (observed, 2026-11-24): `https://thumbnails.libretro.com/` now serves an empty index and answers 404 for every boxart (checked SNES, N64, the directory itself), so every cover was dead, not slow. The libretro thumbnails repositories on GitHub (`libretro-thumbnails/<Set_Name>`, raw files, ~0.3 s, 17 of 17 platform sets exist) are the live source. `Platform.CoverURL` now points there, with libretro's file-name rule (`&*/:`<>?\|` become `_`) and URL escaping. S6 implemented: `romcovers` adapter (disk cache, markers, 4 upstream slots, shared fetch, outbound HTTP only through `romfetch` per the depguard rule), `query.ObtainCover`, `service.WithCovers`, `GET /cover`, cards with a 4:3 frame, skeleton shimmer, fade-in and title placeholder, `object-fit: contain` so landscape boxart is not cropped.
